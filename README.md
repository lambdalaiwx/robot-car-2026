# robot-car-2026
比赛代码和流程备份（工创赛智能物流搬运+CRAIC全地形小车）
# 赛后总结：遥控小车项目

## 一、项目概述

基于开源遥控小车项目（withWirelessSPI1），根据比赛需求进行全面改造：
- 重新定义舵机引脚、量程和初始值
- 增加 OpenMV 二维码识别 + OLED 显示
- 设计模式切换系统，用有限输入控制多舵机
- 增加越障后轮舵机，提升爬坡能力

## 三、遇到的问题与解决方案

### 问题1：舵机引脚与量程不匹配

**现象：** 直接使用借鉴项目的代码，舵机不动或行为异常。

**原因：** 原项目舵机配置（D3/D7 同步臂、D8 夹爪、D12 辅助）与实际硬件完全不同。

**解决：** 全面重写舵机定义，每个舵机独立配置引脚、量程、初始值，从同步控制改为独立控制。

**教训：** 借鉴代码前必须先梳理清楚自己的硬件接线，不要假设引脚分配一致。

---

### 问题2：模式切换设计反复迭代

**过程：**

| 版本 | 设计 | 问题 |
|------|------|------|
| v1 | S1短按切模式，S1长按+10°，S2-10° | 长按操作不直观，手感差 |
| v2 | S1双击切模式，S1短按+10°，S2-10° | 双击检测有延迟，+10°步进不够灵活 |
| v3 | 右摇杆Y+X同时控制两个舵机 | 同一模式控两个舵机效果不好 |
| v4 | 每个模式只用Y轴控一个舵机 | 最终方案，简单可靠 |

**教训：** 人机交互设计要尽早用实物验证，不要在脑子里设计。操作方式越简单越好，比赛中紧张环境下复杂操作容易出错。

---

### 问题3：前进后退方向反转

**现象：** 推摇杆向前，小车往后走。

**原因：** 摇杆的物理方向与电机接线方向不一致。后续大轮换到车尾后方向再次反转。

**解决：** 在 `readDriveCmd()` 中交换 CMD_FORWARD / CMD_BACKWARD 的映射。

**教训：** 电机方向与物理安装强相关，改了轮子位置就要重新确认方向。可以在代码中加注释说明物理朝向。

---

### 问题4：爬坡力度不足

**现象：** 小车无法爬上台阶。

**原因：** 原代码使用 `digitalWrite`（只有 HIGH/LOW），电机要么全速要么停。

**解决：**
1. 改用 `analogWrite` PWM 调速，`MOTOR_SPEED = 255` 满速运行
2. 增加越障后轮舵机 D11，配合前轮越障舵机 D7 完成翻越

**教训：** `digitalWrite` 适用于简单开关场景，需要调速或最大功率时必须用 `analogWrite` + PWM。

---

### 问题5：夹爪通电即夹死

**现象：** 一开机夹爪就夹到最紧，无法通过遥控打开。

**排查过程：**

| 尝试 | 结果 |
|------|------|
| 量程 30°~90° | 夹死不动（量程完全错误） |
| 量程 100°~180°，用 writeMicroseconds | 初始位置正常，但遥控无效 |
| 量程 0°~255°，用 writeMicroseconds | 仍然无法控制 |
| 量程 0°~180°，用 write | 最终正常工作 |

**根因分析：**
1. **量程错误：** 实际有效范围是 100°~180°，代码写的 30°~90° 完全在无效区间
2. **驱动方式不兼容：** `writeMicroseconds()` 与该夹爪舵机不兼容，`write()` 正常

**教训：**
- 舵机量程必须实测确认，不能靠猜。建议写一个简单的测试程序 `servo.write(0)` → `write(90)` → `write(180)` 逐个角度验证
- `writeMicroseconds()` 虽然理论上更精确，但不是所有舵机都兼容。出问题时优先换回 `write()`
- 借鉴代码中的量程和初始值仅供参考，必须根据实际舵机型号和安装方式重新标定

---

### 问题6：D3 舵机开机卡死

**现象：** D3 关节1 一开机就打到极限位置，发出滋滋电流声。

**原因：** 初始值 120° 可能接近该舵机的机械限位，加上舵机安装角度差异，导致堵转。

**解决：** 通过串口调试命令 `J<角度>` 测试不同角度，找到安全初始值。

**教训：** 首次上电前应先用手转动舵机臂确认机械范围，避免堵转烧毁舵机。初始值应设在量程中间位置。

---

### 问题7：烧录后按键全部失灵

**现象：** OLED 和扫码正常，但所有遥控操作无效。

**排查：** 代码逻辑检查无误，判断为硬件链路问题。

**可能原因：**
- 烧录后忘记重新插上无线模块
- 无线模块未配对
- TX/RX 接线反接

**教训：** 烧录时需要拔无线模块（D0/D1 冲突），烧完后必须记得插回。建议在接线旁贴标签提醒。

---

### 问题8：SoftwareSerial 与硬件 Serial 引脚规划

**设计：**
- `Serial`（D0/D1）→ 无线模块，Master-Slave 通信
- `SoftwareSerial`（A0/A1）→ OpenMV，二维码数据

两者完全独立，互不干扰。但烧录时 D0/D1 被 IDE 占用，需要临时断开无线模块。

**教训：** 多串口设备的引脚规划要在项目初期确定，避免后期冲突。SoftwareSerial 会占用定时器，可能影响 PWM 输出，需要测试验证。

## 四、通信协议

Master 每 50ms 发送一帧 CSV：

```
cmd,j1,j2,j3,gripper,obstacle,obstacle_rear
```

| 字段 | 范围 | 说明 |
|------|------|------|
| cmd | 1~5 | 行驶命令（1前进 2后退 3停止 4左 5右） |
| j1 | 75~180 | 关节1 |
| j2 | 15~160 | 关节2 |
| j3 | 10~170 | 关节3 |
| gripper | 0~180 | 夹爪 |
| obstacle | 0~180 | 越障前轮 |
| obstacle_rear | 0~180 | 越障后轮 |

Slave 调试命令（串口直连时使用）：

| 命令 | 功能 |
|------|------|
| `G<角度>` | 设置夹爪 |
| `J<角度>` | 设置关节1 |
| `K<角度>` | 设置关节2 |
| `M<角度>` | 设置关节3 |
| `O<角度>` | 设置越障 |

## 六、改进建议

### 硬件层面

1. **舵机标定工具：** 写一个独立的标定程序，逐个测试每个舵机的有效量程和初始位置，记录到表格中
2. **电源管理：** 6 个舵机 + 2 个电机同时运行电流很大，需要独立供电或加电容，避免电压跌落导致舵机抖动
3. **无线模块可靠性：** 考虑增加连接状态指示（心跳 LED），断连时自动停车

### 软件层面

1. **EEPROM 存储：** 将舵机量程和初始值存入 EEPROM，支持现场校准而不需重新烧录
2. **串口调试界面：** 在 OLED 上显示当前模式和各舵机角度，方便现场调试
3. **摇杆标定：** 自动检测摇杆中心值，适配不同摇杆模块的个体差异
4. **错误处理：** CSV 解析增加校验，防止异常数据导致舵机飞车

### 流程层面

1. **先标定后编码：** 上电第一件事是标定所有舵机的实际量程，再写代码
2. **增量验证：** 每改一个舵机就烧录验证一次，不要批量修改后一起烧
3. **备份已知好用的版本：** 每次验证通过后 git commit，出问题可以快速回退
